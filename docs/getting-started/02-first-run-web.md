# 02 · 第一次运行（浏览器界面）

> 本文基于 dsh 0.1.x 编写，如有出入请提 Issue。

## 本节目标

启动 `web` profile，在浏览器里看到 DeepSeek Harness 的界面，并跑通一次对话。

## 第 1 步：启动 web 界面

在终端运行：

```bash
dsh web
```

或者更完整地写：

```bash
dsh --profile web
```

启动后，终端会打印一个本地地址，默认是：

```
http://127.0.0.1:3080
```

> 💡 这个终端窗口就是"服务进程"，**不要关掉它**，关掉界面就停了。要停止时按 `Ctrl + C`。

## 第 2 步：在浏览器里打开

用浏览器访问 `http://127.0.0.1:3080`。你应该能看到 DeepSeek Harness 的 Web 界面。

## 第 3 步：确认 API Key 已配置

如果之前没配置 API Key，界面里会提示你填写，或在首次调用模型时报错"缺少 API Key"。回到 [01 · 安装的第 3 步](01-installation.md) 设置好即可。

如果用的是环境变量方式，请确保**在同一个终端里**先设置再启动 `dsh`：

```bash
# macOS / Linux / Git Bash
export DEEPSEEK_API_KEY=sk-xxx
dsh web
```

```powershell
# Windows PowerShell
$env:DEEPSEEK_API_KEY = "sk-xxx"
dsh web
```

## 第 4 步：发第一条消息

在界面的输入框里输入一句话，比如：

```
用一句话介绍你自己
```

按下发送，等待模型回复。回复出来了，就说明整个链路（安装 → 配置 → 模型调用）已经跑通 🎉。

## 第 5 步：试试让它"干活"

Web 界面不只是聊天。你可以给它一个有实际动作的指令，观察它调用工具、读文件、执行命令的过程。例如：

```
查看当前目录下有哪些文件，然后用一句话总结
```

你会看到它开始执行命令（比如运行 `ls`），而不是单纯"生成文字"——这就是 Agent 和普通聊天的区别。

## 验证清单

- [ ] 终端里 `dsh web` 正常启动
- [ ] 浏览器能打开 `http://127.0.0.1:3080`
- [ ] 成功收到一次模型回复

## 常见报错

| 报错 | 原因 | 解决 |
|---|---|---|
| 打开网页显示"无法访问" | 服务没启动或端口不对 | 确认终端里 `dsh web` 还在运行 |
| `EADDRINUSE ... :3080` | 端口被占用 | 换端口，或先关掉占用 3080 的程序 |
| 提示缺少 API Key / 认证失败 | Key 没配或配错 | 按第 3 步重新配置 |
