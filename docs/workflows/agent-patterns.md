# 常见 Agent 用法模式

> 本文基于 dsh 0.1.x 编写，如有出入请提 Issue。

把 Agent 用好的关键是**把任务说清楚**。下面几个模式能显著提升成功率。

## 1. 写清楚输入 / 输出 / 约束

差的任务描述：

> 帮我看看这个项目。

好的任务描述：

> 读取当前目录下所有 `.ts` 文件，找出函数名超过 40 个字符的函数，输出成 `long-functions.md`，格式为表格：文件名 | 函数名 | 行号。

给 Agent 一个明确的**输入范围、输出格式、落盘位置**。

## 2. 一次只做一件事

把大任务拆成小步骤，逐个用 headless 跑，比一次塞一大堆要求更可靠。每个小任务的输出就是下一个的输入。

## 3. 让它"读代码"而不是"猜"

让 Agent 先读文件再下结论，能避免幻觉：

> 先读 `docs/` 下的所有 `.md`，再根据实际内容写一个目录索引，不要凭记忆编造。

## 4. 让它"边做边验证"

涉及写代码/跑命令时，要求它运行验证：

> 写一个 `hello.py`，然后运行 `python hello.py`，确认输出是 `Hello`，把结果告诉我。

## 5. 结果写文件，便于检查

让 Agent 把结果落到文件，而不是只打印在终端，方便后续人工复核或归档：

> ...把结果写入 `report.md`。

## 6. 明确"不要做什么"

给负向约束：

> 不要修改 `src/` 下的任何文件，只读。

## 组合示例：代码审查辅助

```bash
dsh --profile headless "读取本次改动的文件，按「正确性 / 可读性 / 安全」三个维度各找最多 3 个问题，输出到 review.md"
```
